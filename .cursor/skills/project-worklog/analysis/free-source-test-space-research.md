## 待核实问题

- 新复现矩阵固定六类独立故障：混合器件根、同源干线 split-rejoin、公共根与单连接根的列/行选址冲突、单连接 `from` 首列交叉、零折点直连被折弯、根纵序与目标端口纵序倒置；另建一张交叉覆盖全部维度的复杂公开 example。
- 新 Oracle 必须直接量测：每个物理根锚点的同网路线并集是否为无重汇合的有根树、可见交叉/边对交叉、逐边长度与折点、根诱发交叉、端口顺序逆序、以及允许根列/行/副本变化后的完整反事实支配。旧统计只报总量或排除根父节点，不能授权新声明。
- ELK 官方资料确认 layered 流程把 crossing minimization、node placement、orthogonal routing 与 port order 分阶段处理；模型顺序仅宜作为交叉最少解中的次级偏好。结构决策据此改为“拓扑可行层区间 + 根设施选址 + 根/端口共同排序 + 固定节点后的正交最少折点路由”。

- 同一 edge/points 的障碍查询是纯函数；以 edge key 与完整点列为键缓存不可变命中集，可消除重复空间桶扫描且不改变搜索空间、评分或接受顺序。
- 性能变更的反例是缓存键只含点列而不含逻辑边：相同几何但不同 source/target 的端点豁免集合不同。键必须同时包含 edge key；值必须不可变，避免调用方污染后续评分。
- 可推广结论已写入用户根自由布局专题：先优化重复纯查询和影响域，再考虑缩减候选；最大特征语料需在隔离与全量负载下连续测量。
- 同一代码版本的全量门恢复为 400 PASS；五个目标环境条件门仍由冻结发行 CI 补齐，不能并入本地通过率。
- 打包工具的条件模块警告不能静默忽略，也不能单凭名称阻断；记录清单后由 PATH 隔离的完整 frozen feature smoke 判断真实缺失。临时消费目录的清理若被宿主策略拒绝，可降级为已 ignore 的唯一工作目录并保留证据，不绕过安全策略。
- Windows 包消费已证明冻结入口与零 Python 依赖源码入口都只读取解压根资源；Linux staticx、librsvg 和远端下载后消费仍须由托管 runner 独立取证。
- 内部证据必须在更新公开 report 前移除，避免不可序列化/大体积 assessment 泄漏到用户接口；测试替身需接受新增内部关键字参数。
- 阶段输出不仅是 LayoutDocument，还应携带与该精确版本绑定的 assessment；下一阶段未改图前重新评估是确定性重复工作。候选被接受后必须同步替换两者。
- 可见盒由静态宽度估算与动态坐标组合构成；只缓存前者可跨候选复用并保持移动节点几何正确，缓存整个盒则会产生陈旧坐标。
- 绝对不变量仍需限定候选影响域；把全图无关旧 overlap 归给局部 source 候选，会错误拒绝整组动作并触发大量逐锚点回退。
- 可见 overlap/hit 与反向 hit 都是绝对错误，不是可交换的软成本；基线已通过前序门时，候选直接判空比两次签名后做子集更严格且更省时。
- 对绝对禁止的不变量，候选谓词应直接要求空集；若前序阶段已保证基线为空，重复构建基线索引再做子集比较没有语义收益。
- 几何分类和精确谓词必须共享坐标规范：若先用容差判正交、后用严格等号执行正交求交，浮点尾差会落入“任意斜线命中”保守分支并制造远距离假阳性。
- 对长正交线，二维均匀桶会按几何长度产生大量空桶；焦点矩形求交更适合按段固定轴排序后二分，查询成本由候选轴密度决定而非线长。
- 节点移动的最小完整影响域是“incident edges × 全节点”并上“未改边 × 移动节点”；后者可用焦点盒空间桶求交，不必退化为全边 × 全节点。
- 反例修正：设施经济性不是纯一维问题；不同列的两个显示设施可显著减少横向/纵向交叉，独立 Oracle 只对同列相邻设施做合并判定。合并必须在列选择之后评价。
- 相邻 gap 判据只对区间 span 目标可分解；项目接受指标是到中位设施行的 L1 服务成本。应先形成细候选，再按 `L1(merge) <= L1(left)+L1(right)+opening_cost` 合并并回看相邻栈顶。
- 行距必须基于视觉行带而非所有节点中心的相邻差；同一行不同高度/端口会制造伪小间隔，导致生产过度复制、Oracle 随后判冗余。
- 旧航点与新端口拼接可能形成斜段，不能只查折点数和净空；正交性必须从未简化逐段坐标验证。设施成本需在整根范围比较，不能只看每次切分动作。
- 节点移动的反向影响不是只有 incident edges：任意既有边都可能穿过节点的新可见盒。没有反向空间查询时必须全边比较；端点净空/微段只依赖受影响边，可保持局部。
- 候选硬签名使用集合包含关系而非只比计数，防止“消除一个旧错误、同时在另一位置引入新错误”以数量相同逃逸。
- 局部候选只会改变 incident edges；可见障碍集合仍是全图，但路线签名可限定到受影响边，兼顾完整障碍语义与规模效率。
- 全量逃逸证明基础框 `assess_layout` 不等于用户可见几何：候选接受还需比较受影响边对标签扩展盒的穿越、源/目标水平引线净空和微线段签名；生产与独立 Oracle 实现保持分离。
- 质量向量按优先级可安全短路：硬几何已经劣化时，后续交叉/折点/长度不可能改变拒绝结论；合法候选不得短路软指标。
- 收敛后 scope 仍需读取同一最终图，根级 `cell_id` 索引应复用；只有接受候选改变几何/source_id 后才刷新。组内固定器件的列障碍集合也应缓存。
- 一维可行域无需把每个边界重新对全部区间做可行性测试；合并禁止区间后，最近点要么是原目标，要么是包含目标的合并区间边界。
- 空间检测复杂度：固定布局的器件盒应按候选列和 y 区间索引；每条短接入段扫描全图会让被拒绝候选也付出 `设施数 × 节点数`，且不增加检测精度。
- 分区效率：设施分区只拥有一条继承列上的 y 选择，因此障碍可一次投影为区间；在该阶段枚举 x 会重复后续锚点阶段职责，并把线性放大为锚点数乘节点数。
- 候选经济性：完整候选构造前先证明变量仍有可行改进域。整组动作已把所有设施送到最迟列后，逐设施 scope 的可行域为空；复制和障碍建模属于可消除的零收益工作。
- 性能模型：若锚点阶段重新评估所有单根，会形成 `根数 × 全图复制/评估`；单根列属于拓扑 ALAP，多物理设施列才属于锚点阶段。候选仅修改坐标、source_id 和不可变航点，递归复制器件属性是无效成本。
- 知识沉淀边界：通用设施选址、几何统计和反事实方法进入用户根专题；19 号数值、发行证据和具体回归保留在项目能力合同与工作记录。
- 覆盖闭环：复杂成功样本增加“禁用局部显示设施、其它阶段保持不变”的完整反事实；它验证收益来自通用设施变量，而不是测试只确认最终图没有硬错误。
- 故障注入补项：可见盒对象与底层几何四元组的适配属于接口合同；候选枚举必须经真实复杂样例执行，不能只靠静态路径存在性声明覆盖。
- 列选择反例：拓扑上的最迟可行列可能没有障碍可见通道；列后移是软目标，必须先最小化精确端口接入的器件命中，再在同等正确性下选择更靠后的列。
- 行坐标反例：顺序扫描障碍并在前/后两侧贪心位移，不保证最终位置同时避开之前处理过的区间。固定 x 后应转化为一维禁止区间并一次选择最近全局可行 y。
- 阶段所有权反例：先对全根分区、再对每个既有分区独立二次切割，会丢失跨分区设施成本，产生全局可合并副本。设施开启由一个阶段拥有；后续阶段只优化每个设施的位置与路线。
- 设施经济性：局部行分区与独立冗余检测必须共享同一几何成本模型；当前采用 3 个动态行距，避免生产认为“应拆”而 Oracle 认为“可并”的合同分裂。
- 路由所有权反例：显示锚点换行/换列后继续复用旧内部航点，会让“新端口到旧通道”的接入段成为未建模障碍；显示设施位置与连接路线必须联合重算，旧路线只能是候选或反事实，不能是硬约束。
- 反例：若后移阶段只处理已有多个显示锚点的 source，则单连接、低复用 source 永远继承最左根列；这会从候选空间中系统性排除“紧邻唯一消费者”的最优解。正确边界是零入度且无显式列约束，而不是物理锚点数量。

1. 零入度节点在什么约束下可从第一层后移，同时保持所有边从左到右并减少总层跨度？
2. 如何精确而可扩展地给每条正交线归因长度、折点、交叉点、交叉事件和不同相交边数？
3. 如何从项目特性空间构造可审计测试集，而不是从已有测试名称反推“覆盖全面”？
4. 一个逻辑零入度节点被拆为多个显示锚点后，如何让每个锚点独立占用最迟可行列，而不是全部继承逻辑节点的单一 rank？
5. 如何证明 source 区域的长线/交叉来自布局选择而非不可避免拓扑，并由完整重排重路由反事实拒绝？

## 23:24 新发现

- 已验证：`_replicate_dispersed_roots` 复制显示顶点并重算 y/路线，但不为每个分区重算 x；别名继承原逻辑根 rank/x。
- 已验证：生产分组扫描与独立精确边对枚举对同一最终图分别得到 245 与 227 个边对事件。不同交叉坐标仍为 100，说明差异位于同坐标多边/共享结构的事件计数语义，而非几何点漏报。
- 决策：先冻结一个能杀死旧 Oracle 的精确边对故障样本并统一统计合同；统计器自身未闭合前不得用事件数评价 source 布局收益。

## 23:31 方法对标结论

- ELK Layered 的 node promotion 在分层后减少 dummy nodes；yFiles `HIERARCHICAL_OPTIMAL` 最小化全边层跨度，并把 layering/sequencing/drawing 分离；二者支持把低复用根或其显示设施后移，而非固定第一列。
- yFiles edge grouping 允许共同源端的边级联形成总线，但强调不能形成语义歧义；本项目只允许同一逻辑 source-port 网共享，显示锚点不创造逻辑节点。
- 电路正交超图研究以每层间一条 net track 降低折点和交叉；libavoid/正交可见图负责固定节点后的障碍路由。采用边界是：它们提供分层、分组和路由先例，最终列/行仍由本项目端口、器件几何和完整质量向量验证。
- Find Skills 两轮均因用户级不完整 `node_modules\\npm` 缺少 `npm-prefix.js`/`npx-cli.js` 在查询前失败；不安装或修复用户运行时，使用本地已安装领域 skill 与在线官方/论文/主仓库资料降级。

## 23:40 实现假设

物理锚点的可行列由当前图规范列、分区内最早目标列、源/目标可见轮廓和 route clearance 共同决定；不读取器件名、实例名、样例号、固定像素列或图规模。同行位以该列实际重叠的器件、标签、既有边和先放锚点为障碍。路线重新从端口计算并在分区内共享一根纵向 trunk，避免移动锚点后沿用旧航点造成回退或额外折点。

首轮失败证明“统一重建中间 trunk”改变了过多路由所有权。第二轮把旧航点结构保留为候选，只裁掉移动后位于端点前后之外的点，并把首个通道夹在新源与目标可见轮廓之间；后续再与靠源/靠目标结构通道比较，而不是强制一种 trunk。

第二轮反例证明 placement 不能读取即将被替换的旧路线作为硬障碍，否则形成阶段循环：旧路线决定新节点，新节点又决定新路线。结构顺序固定为 `alias partition -> feasible column -> node/label-safe row -> reroute -> complete quality comparison`。

候选回退不再靠重新运行另一套近似参数，而是把继承列完整图作为阶段输入；后移阶段只能在该图上做严格单调改进。这样任意新 JSON 若没有可证明收益，会保持原设施分区结果，不会因新增优化丢失已有副本。

## 已核实事实

- 本地 `_ranks` 已执行终端对齐后的 ALAP 反向传播；这能把有松弛量的任意零入度节点移到最迟可行层，不依赖器件名。
- yFiles Hierarchical 的 optimal/tight-tree/downshift 分层以总层距离为目标，并允许未约束节点出现在图中央；ELK Layered 把分层、交叉最小化、坐标和路由分成独立阶段，并提供 node promotion。二者支持“源不等于第一层”的结构性处理。
- NIST ACTS/covering array 要求显式参数模型和 t-way 组合覆盖；其官方建议明确反对只从 use case 建输入模型。Hypothesis 提供数据与状态序列生成，pytest 参数化提供稳定场景 ID；它们不能替代需求/风险账本和独立 Oracle。
- 当前逐边报告缺少不同相交边数，逐源聚合也不能覆盖叶节点。交叉点和边对事件是不同量纲，不能互相替代。

## 候选路线

- 采用：保留 DAG ASAP/ALAP 与完整候选质量向量；为自由源列新增公开反例和坐标 Oracle，而不是按 `from` 名称加规则。
- 采用：扫描线交叉组使用每边位集合累计不同对端，避免物化高扇出的边对列表；内部报告和独立 Oracle分别实现。
- 采用：机器可读特性/交互/场景账本加故障注入校验器；低风险 pairwise，高风险已知相互作用显式三元或端到端覆盖。
- 拒绝：把所有源固定到第一列，或只用节点数/代码覆盖率/测试数量声称全面。
- 拒绝：把 React Flow 当作布局算法；它是交互呈现层，仍需 ELK/Dagre 等布局后端。

## 18:49 再研究：多层自由根与完整反事实

- React Flow 官方明确自身不实现布局，只集成 Dagre、ELK 等；Dagre 偏简单树与速度，ELK 支持动态尺寸、端口和路由，因此 React Flow 不是本缺陷的算法 owner。
- yFiles `HIERARCHICAL_OPTIMAL` 以所有边的层距离总和为目标，OGDF `OptimalRanking` 以 LP 求最小边长 ranking，Graphviz `dot` 以 network simplex 排 rank 后再做 mincross/坐标。这三条成熟路线共同支持“在前向约束内按全局边跨度选择内部层”，而不是“零入度等于第一层”。
- ELK Layered 仍适合作为端口/正交/层内顺序基准，但只切换 `NETWORK_SIMPLEX` 或 node-placement 选项不能证明最终图更好；必须从最终几何复算交叉、折点、长度和障碍物命中。
- 旧 23 号 fault 仅改节点 x，未同步路由，是弱 Oracle。采用完整反事实：复制同一拓扑，仅用公开相对列约束把全部根固定为同列，重新运行整个布局与路由，再与无约束候选按交叉、折点、长度比较；产品仍只采用无约束拓扑规则。
- Find Skills 的前两条查询找到 OpenAI node-link/diagram、AntV G6、Syncfusion 等候选；后两条查询连续 60 秒无输出后有界终止。未安装第三方 skill；现有领域 skill 更贴合，失败检索不影响官方资料与本地实验，但候选生态覆盖不完整。

## 20:49 特性空间修正

19 的新需求拆成三个可独立失败的维度：多逻辑源、连续/交错的终端行归属、多源经多输入器件汇聚后再扇出。原 19 的单逻辑源显示副本属于第四个正交维度，应迁移而不能删除。测试集必须分别断言逻辑根身份、输入端口映射、终端根祖先集合、最终 SVG 端口/边数量和几何质量；不得只靠截图相似或节点名称放行。

四个维度已经分别映射到 19、24、端口几何测试、逐边统计与发行包消费。最终 19 的输入拓扑保持 A/B/A/B/A/B 的交错编号祖先关系；自由排序将同源消费者聚簇以得到 0 交叉，说明“输入行归属”和“视觉排序”必须由两个 Oracle 分别判断，不能把降低交叉误报为改错连接。

## 21:42 复杂交错特性矩阵

不能用固定 A/B 周期充当“不定间隔”。新语料分别登记：单源连续、单源非周期稀疏、两源/多源交错、根集合部分重叠、完整与稀疏 pad 输入、pad 一对多、pad+source 二次汇聚、不同链深、不同源复用度。拓扑 Oracle 从终端反向计算根祖先集合，并量化直连序列切换率、每根消费索引 gap 集、共同后代根对数和祖先签名多样性；几何 Oracle 独立检查最终逐边/逐源统计。重命名、JSON 逆序和端口对象逆序不得改变上述结构量纲或硬门结果。

最终语料的 8 根覆盖 25/28 个根对、24 种终端祖先签名和 3～11 的全部非周期直接消费间隔；旧 12 终端浅层语料由突变门拒绝。组合变形暴露并推动修复了短异网共线阈值盲区，证明“复杂语料 + 独立 Oracle + 变形”比固定名称枚举更能发现通用缺陷。

## 04:20 结构性解法与覆盖结论

- source 不是固定第一列的器件类别，而是图论上的零入度逻辑节点；显示副本是同一逻辑输出端的局部设施，不改变拓扑，也不允许中间节点或终端复制。
- 单个逻辑 source 的多个设施必须分别求解列、行和路线。只复制图案而继承原 x，或只移动节点而复用旧航点，都会保留长干线、制造接入凸折和障碍命中。
- 固定 x 后的 y 选择是禁止区间的最近点问题，不能按障碍顺序贪心推开；后者会重新落入先前区间并产生输入顺序依赖。
- 交叉统计必须保留三种语义：边对在交叉点的事件数、不同相交边对数、不同交叉坐标数。逐边报告使用不同伙伴数，图级拥挤使用坐标数，不能互相替代。
- 覆盖以特征空间为入口：连续与非周期行带、源复用度、稀疏端口、pad 汇聚、pad 再与根汇聚、深度变化、远近消费混合；再叠加完整反事实、重命名与顺序变形、故障注入、规模压力和发行消费，而不是为某个 JSON 名称写分支。
- 性能优化必须保持同一质量接受函数；缓存、增量影响域和不可变数据共享可以减少计算，不能把面积或耗时提升到交叉、正确端口和拐点之前。
- 性能门必须在全量负载下留有余量；一次独立快跑低于预算不能证明稳定。相同 edge/points 的障碍查询是纯函数，可用不可变结果缓存消除可见图扩展、trunk 筛选与评分之间的重复工作，而不改变搜索空间或质量排序。

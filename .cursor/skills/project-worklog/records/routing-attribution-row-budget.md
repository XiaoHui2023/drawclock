## 当前事实

- 原实现只报告总体交叉点和根源交叉点总数，无法定位具体高风险边或逻辑源。
- 原分散根源拆分以水平服务距离参与固定成本，只有很大的垂直空带才容易形成候选，不能表达“稍远就优化”的可视行语义。
- 已开始加入每边、每逻辑源的交叉点、相交边、垂直跨度、夹行数统计，并将候选边界改为几何归一化的三行预算与实际夹行数双判据。
- 首轮聚焦测试为 1 通过、5 失败；失败均由 `src/auto_layout.py` 漏导入 `statistics.median` 引起，错误为 `NameError: name 'median' is not defined`。该失败发生在布局评估入口，尚未形成错误制品。
- 已补齐 `statistics.median` 导入并移除未使用的键映射，下一步复跑同一测试确认恢复。
- 第二轮聚焦测试为 3 通过、3 失败。诊断发现直接去重节点中心会把同一视觉行内约 8 px 的器件/端口偏差当成独立行，造成过度拆分；现改为先按中位器件高度聚类成视觉行带，再以行带中心和典型间距计算预算。
- 行带修复后聚焦测试 6/6 通过。现将交叉归因改为线性空间统计：每边记录不同交叉点和交叉对事件数，每源聚合；避免为了列举所有相交边而在大扇出上物化笛卡尔积。独立 Oracle 已按可见几何另行复算同一合同。
- 已增加两个强负载判据：手工注入一处异网正交交叉，要求两条边与两个源都各归因一次；把分散消费者仅下移约四个典型行距，要求无需“超远”间隔就能形成并接受一个安全渲染副本。
- 首个中距离样本使用 400 px 总位移，但扣除原有消费者排布后相邻带净间隔为 288 px，未超过实测三行预算 309 px，因此正确未触发；边界改为 425 px（净间隔略高于预算），保留“等于/以内不拆、刚超过即候选”的严格语义。
- 聚焦门禁现为 9/9 通过，包含 1024 规模硬几何检查。公开项目 skills、设计笔记、质量合同与用户根部 `clock-tree-layout` 已同步三行预算、视觉行带、逐边/逐源归因、独立 Oracle 和线性空间统计规则。
- Find Skills 分别检索 graph drawing crossing metrics、layered graph layout optimization、orthogonal routing quality，命令均成功但没有返回专门覆盖分层正交路由质量的可用 skill，因此未安装泛化网页布局/绘图 skill，继续使用现有专用 `clock-tree-layout`。官方 ELK 分层阶段、交叉最小化、固定端口正交路由以及分层图 edge span 定义已作为方法基准。
- 项目七项 skill 与五件套校验均通过。用户根部 skill 首次校验误用非系统路径报 `No such file or directory`；改用正确系统路径后又因 Windows 默认 GBK 读取 UTF-8 报 `UnicodeDecodeError`，设置 `PYTHONUTF8=1` 后恢复并通过 `Skill is valid!`，对交付无残留影响。
- 首轮全量测试为 359 通过、17 失败（111.21 秒）。15 项质量失败来自独立副本 Oracle 仍使用旧水平距离固定成本，与生产三行预算不一致；2048/4096 两项性能失败分别为 10.207/37.880 秒。现把 Oracle 固定成本统一为三倍独立测得行距，并将详细逐边归因从所有临时候选移到最终布局一次生成；候选仍计算原有聚合硬指标。
- 详细统计开关重构的首笔修改一度保留了提前 `return`，静态查看立即发现不可达附加逻辑；同轮修正为先构造 `report` 再条件附加统计，尚未作为通过证据。
- 失败集合复跑为 1 通过、15 失败；共同错误是最终 `routing_statistics` 键缺失。检查发现通用文本补丁误把 `_place_nodes` 的 `return` 改成局部 `report`，却未命中 `assess_layout` 的目标返回。现按相邻函数语境精确恢复 `_place_nodes` 返回并修改评估返回；后续结构性替换必须在修改后读取命中区段，不能只依赖编译。
- 精确修复后受影响集合 13 通过、3 失败。两项列布局失败来自聚类后 37.499 px 行距小于典型器件高度，普通 126 px 分支被拆成三个锚点；多源样本虽质量通过但 4 个逻辑源膨胀为 48 个物理 y 位置。现将行距下界设为中位器件高度，并限制每个逻辑源一次最多两个锚点、选择最佳连续切分；原多源断言改为只比较四个原始逻辑源位置，同时限制副本总数不超过四。
- 行距/双锚点修复后的受影响质量集合 16/16 通过（45.70 秒）；1024/2048/4096 规模性能组 3/3 通过（合计 36.04 秒），各自均低于既有 5/10/30 秒预算。已移除 Oracle 中随旧成本定义遗留的未使用水平距离变量，准备全量复验。
- 全量回归 376/376 通过（104.21 秒）；`compileall`、`git diff --check`、项目七项 skill、五件套及用户根部专题 skill 均通过。代码与文档进入提交和滚动 Release 闭环。

# 设计笔记

## 产品范围

- drawclock 只把时钟连接配置和指定的 draw.io 器件库转换为 SVG。
- 唯一入口是 `python src` 或安装后的 `drawclock`。绘图是主功能，无子命令。
- 必填参数为 `-i/--input`、`-l/--library`、`-o/--output`；`--crossing-style` 保留 `arc`、`gap`、`sharp`、`none`，默认 `arc`。
- 输出内容始终是 SVG，文件后缀不改变格式。
- 最终 SVG 只使用自包含的静态原生 SVG 图元与文字，不含 XHTML `foreignObject`、脚本或外部资源；无法转换的器件标签显式报错。
- 配置只接受严格 JSON，由 Python 标准库 `json` 读取，不含第三方 Python 运行时依赖。
- v0.0.0 tag 与 Release 保存旧的 extract/reload 版本；v1.0.0 起源码、CLI、示例、测试和发行包只含绘图功能。

## 配置与器件库

- 顶层字典键是实例名。每个器件只要求 `kind`；根器件可以省略 `source`。
- `kind` 直接对应 `--library` 中的器件 title，不按名字、连接端口或内置器件表猜测。
- 每个器件库 XML 只包含一个器件，使用标准 draw.io `<mxlibrary>` 包装且数组长度为一；内置库位于 `drawio-lib/drawclock/`。
- `--library` 接受一个或多个单器件 XML 文件和目录，也可以重复指定；目录递归扫描 XML，按稳定路径顺序合并。相同文件去重，不同文件出现同名 title 时报错。
- 多输入器件的 `source` 使用稀疏字典，未列出的有效输入端口可以不连接。
- 内置 `pad` 保持零输入单输出；`pad3` 是独立三输入单输出汇聚器件，外部库仍可按同一端口合同定义任意多输入 title。
- 多输出引用写成 `器件名[输出键]`。
- `component`、`*_kind`、`freq`、`ratio` 等不是通用必填字段；附加属性由当前器件库定义。
- `layout_column` 是可选整数等级。较小值靠左，较大值靠右，相同值尽可能共列。数值只表示顺序，不保留数值间的空列；省略时只按连接关系布局。
- `from` 与 `source` 都按普通零入度器件处理，不含导出或跨图特殊语义。

## 布局与布线

- 图从左到右分层；器件位置、端口、标签范围和路线全部由当前配置与器件库计算。
- 禁止按实例名、器件类型、示例文件或节点数量写专用分支。
- 优先级依次为端口正确、无器件或文字穿越、无节点重叠、不同网络不重合、减少交叉、减少拐点、路线整齐；长度和画布面积排在这些指标之后。
- 同一输出端口连接多路下游时，共用一条纵向分发主干，各目标保留独立横向支线。
- 零入度器件的消费簇相距很远且服务代价更低时，可以创建保持逻辑身份不变的显示副本；中间与末端器件不能复制。
- 零入度显示副本的分区不能用固定行数决定。相邻或近邻且排列工整的消费带优先保留单一显示设施与共享纵干线；以同源端口正交线段并集长度计算共享走线一次，以当前器件和标签的真实可视框周长计算每个显示设施的开设成本。只有拆分在完整质量向量上严格支配合并时才创建副本。
- 单次布局中的源显示锚点数由上述设施目标与实际消费端口轴共同决定，不设固定上限；每个锚点必须服务逻辑边且相邻锚点不可无损合并。四五行只是覆盖输入，不是算法阈值；任意器件库尺寸变化后目标函数仍成立。
- 所有正交几何基元必须用同一显式浮点容差判断水平和垂直。禁止用坐标精确相等把 `1e-13px` 级端口计算尾差误判成斜线、碰撞或必要折点；真实斜线仍保守拒绝。
- 非对称分支中，若一个中间器件同时连接继续向后的支路和跨越中间列的末端，布局器按入度、出度和列跨度找出独占上游链。整组移动后只在硬几何指标不变差且总拐点严格减少时接受。
- 整组换行候选只用于结构质量模式；高复用域模式不执行全局候选扫描。模式由连接集中度和跨层工作量决定，不以节点数设分界。
- 单点联合优化处理四个以上拐点的异常；两折点路线另由独占链、物理根设施或多入边下游视觉行等结构性 owner 处理，不做逐边无约束全局枚举。
- 多入边目标若所有输入源端轴到目标端口轴具有相同非零偏移，则尝试平移完整下游拓扑；若既有支路线会穿过移动后的器件/文字，所有权递归吸收该支路目标与后代。仅在完整质量向量非退化且总折点严格下降时接受。
- 两拐点边还要检查坐标可移动性：若源节点属于从零入度节点开始、每个节点只有一个下游的完整独占链，整链移动到目标端口轴后只在具体重叠对象、穿线对象、异网重合、交叉和公共主干均不增加且总拐点减少时接受。硬错误按对象对比较，不只比较总数。
- 同等级节点收缩为约束节点，相邻等级增加一条次序边，一次最长路径扫描计算最早可行列，复杂度为 `O(V + E + L)`。相同等级存在因果依赖或较大等级必须位于较小等级上游时，连接方向优先，不强制满足等级。

## 质量检查

- Agent 检查端口坐标零偏差、水平引出、每条逻辑边恰好一次、正交线段、器件与文字穿越、节点重叠、异网重合、交叉、锯齿、可避免拐点、源主干碎裂、显示副本合法性和 SVG 边界。
- Agent schema 13 逐边记录交叉点、交叉对事件、纵向像素/行距与夹行数，并逐逻辑源聚合出边风险；独立 Oracle 从最终几何复算，统计不得物化大扇出的相交边笛卡尔积。
- SVG 兼容门同时检查浏览器 CTM、静态元素禁用集和 GNOME librsvg 的实际绘制结果；浏览器可打开或渲染命令退出 0 不能单独证明器件可见。
- 可避免拐点分为固定节点路线、单节点联合、独占根链、物理根设施与下游视觉行闭包候选；每类都有独立正例、冻结故障或边界反例。
- 相邻行高器件的折线不得只按名义单元矩形或器件种类判断；独立 Oracle 使用当前库的真实可视图形、标签、端口轴和净空，直线碰撞时允许绕行，直线无碰撞且完整质量向量占优时拒绝折线。
- 行距/L1 设施合并值只用于筛选反事实候选，不具备硬失败资格；近距设施冗余必须由最终 SVG 上的完整合并反事实证明。完全同坐标副本无需寻路反事实即可拒绝。
- 路线质量不能只按整条边分类。按有序交叉点、分叉、合流和端口邻域切分后的首段、中段、尾段分别计算折点下界；局部候选保持区段外路线、交叉顺序和网络连接不变，仅在完整碰撞、重叠与新增交叉均不退化时判定可避免折点。
- 故障注入覆盖错误端口、缺边、重复边、斜线、文字穿越、终端排序交叉、汇聚外凸、源主干重复和显示副本身份错误。
- 性质语料改变器件名字、类型、尺寸、端口、链深、根复用和连接顺序。
- 列等级检查包括不同前后深度、无提示基线、输入逆序、远距整数、不同器件、因果冲突、整列位移和等级逆序；Agent schema 11 分开报告同等级错位与相邻等级逆序。
- 压力配置覆盖 512、1024、2048 和 4096 个末端时钟。4096 生成预算为 30 秒；美观与几何正确不为更小画布让步。
- 19 组合覆盖 8 个独立源在 48 行中的非周期交错、不同复用度、完整/稀疏 `pad3`、重叠根集合、PAD 扇出及 PAD+source 二次汇聚；拓扑门基于祖先签名与间隔统计，不依赖实例名。24 单独覆盖一个逻辑源的显示副本，禁止混淆两种语义。
- 质量检查只存在于测试与 Agent 记录，不是公开 CLI 功能。
- 用户对结果表达持续错误、异常、未复现或质量不过关时，按语义登记为独立 issue；每条均记录假设、正常入口尝试、观察、分析、未复现原因、证据和下一条件。
- 未取得冻结基线经公开 CLI 的两次自然红灯前，禁止修改该问题的产品 owner；人工改 SVG、故障注入和 Oracle 变异只验证检测器，不能充当用户问题复现。
- 反馈问题与测试载体采用多对多关系：问题 ID/直接判据保持独立，一张最终 SVG 可直接覆盖多个问题，一条问题也可出现在多个正常 JSON 中。总体覆盖只接受 `case -> observed issue IDs` 中由 Oracle 直接检测的边。
- `tests/reproduction-corpus/` 的 60 个 JSON 交叉覆盖根类型、复用度、固定端口、链深、消费行距、可行列和插入顺序；`tools/check_feedback_reproduction_corpus.py` 验证完整笛卡尔积和正式映射，删除问题映射或降级 one-to-one 必须失败。
- `tools/feedback_layout_reproduction_oracle.py` 不导入生产模块，只读最终 SVG，先完整绑定节点/边/端口，再区分内部交叉、端点接触、共线重叠和同网分支。多余折点与根位置只以无碰撞、无高优先级退化的严格反事实支配判定。
- 搜索语料先覆盖全部反馈，再比较失败样本与没有症状的样本，最后制作综合 example；综合 example 不替代不同历史 revision 的正式收据。

## 发布

- PyInstaller 可执行文件内含本项目 Python 模块，不依赖宿主 Python、Node.js、ELK 或浏览器。
- 发行包包含主程序、原始 `src/`、`drawio-lib/`、全部公开示例、源码部署说明和根目录 `skills/`；不含 Runtime、npm 清单、Python wheelhouse 或依赖清单。
- `skills/` 包含器件库、布局算法、JSON 合约、时钟图设计、SVG 成品、SVG 兼容性和项目导航七个渐进披露 skill；只含项目知识，不含私人路径、身份或本机自动化信息，也不是绘图运行时依赖。
- 源码部署只要求 CPython 3.10 或更高版本；以 `-I -S` 禁用用户目录和 site-packages 后仍可直接生成 SVG。
- `source-manifest.json` 逐文件记录源码、项目 skill、器件库目录内各组件 XML 与示例的 SHA-256，缺失和篡改均阻断源码消费门。
- 冻结包门和源码包门都执行包内 skill 校验器，检查固定目录集合、frontmatter、单层 references、链接完整性、UTF-8 和私人绝对路径。
- 发布前从真实 ZIP 解压，在隔离 PATH 下测试直接入口、任意输出后缀、严格 JSON 拒绝规则、文件与目录混合器件库、默认圆弧、示例、复杂图及 512/1024/2048/4096 四档压力图，并拒绝任何 Runtime/npm 污染。
- 本地 `pack.sh` / `pack.bat` 在创建环境、下载依赖或修改 `dist/` 之前执行自包含 release 门；任一反馈未自然复现、未修复验证或未关闭均非零退出。
- GitHub Actions 的反馈门是 build 的必要前驱，publish 同时依赖反馈门与 build；发布 job 禁止用 `always()` 绕过失败传播。
- 同一解压包还要创建空虚拟环境，通过 `python -I -S src` 生成可解析的 SVG，证明源码不借用第三方 Python 包。
- 每次修改通过检查后读取用户根 `github-upload` 与 `github-release` 规则，提交、推送并发布当前 `pyproject.toml` 版本。

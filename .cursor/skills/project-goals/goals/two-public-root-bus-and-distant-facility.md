# 双公共根总线与远距显示设施

## 状态

- status: active
- owner: agent
- updated: 2026-09-17

## 期望结果

- 对重复两输入 MUX 行，若两个零入度根都跨至少两行重复服务同一批 merge 行，则两个根各自形成一条纵向总线；不能把其中一个误当作可按行拆分的私人根。
- 两条总线的位置由完整几何、端口轴和 MUX 队列决定：可以一左一右，不能为强制首列制造交叉、折点或不必要空白。
- 一个公共根同时服务相距很远的上、下消费带时，若同名显示设施的完整几何成本严格更低，允许拆分为多个设施，避免无交叉但很长的中间主干；规则不得按 `from`/`source` 名称或固定行数特判。

## 当前证据

- failure: 当前 `9b91636` 的公开生产布局对 4 行“双公共根→各自 gate→mux2”输入返回 `regular_bus_roots=[]`，`public_from` 与 `public_source` 各显示为四个同名设施，而不是两条总线。自然生成物来自未改写的 `generate_elk_layout`；先前质量注册表未把“第二公共根重复服务同一 merge 行”列为总线识别语义，属于 `oracle_escape + coverage_escape + ownership_escape`。
- failure: 旧 `_regular_fanout_array_roots` 只接受逐行低扇出私人根作为另一输入；第二公共根跨多行复用时未被识别。旧设施分区流程又将规则总线根整体排除，尚未验证“远距公共根拆分同名设施”的新要求。
- success: 拓扑修复后，定向测试通过；两个根均被识别为规则总线根且各仅一个设施。独立质量检查器在同一输入上通过，碎裂总线、规则阵列复制和硬失败均为空。
- failure: 上/下远距消费带的所有权探针仍被最早 `_replicate_dispersed_roots` 的结构总线排除。该阶段必须改为“紧凑阵列保留总线、远距设施候选参与全局支配比较”，不能用统一禁令。
- success: 移除最早 owner 的绝对排除后，1500px 远距 probe 中两个公共根各产生一份同名设施；独立质量检查通过且无 split–rejoin。紧凑双公共根反例仍各保留单设施。
- failure: 初版公共/公共泛化随后被既有反向声明的公共/私人六行数组否决：`shared` 被复制为六设施。原因是识别器替换了已验证的公共/私人遍历语义，不能只凭局部用例绿灯宣称通用；下一版须保留旧判定并仅增加与其正交的公共/公共重复 merge 证据，且把该反例纳入每次全量相关质量门。
- success: 结构总线的同名设施拆分现仅在 repeated branch-to-mux array 中由全局设施 owner 评估；常规行距保留共享主干，显著空带可拆分。后续局部 owner 跳过结构总线，不能重开被全局拒绝的分区。公共/私人、公共/公共、紧凑、远距与声明乱序共 11 个定向门通过。
- failure: 曾把 direct collector bus 同样开放给远距分区，令冻结 `pad-r08-s02` oracle 从 16 变为 12 crossing。即使表面变少，也属于未审定的公共图语义漂移；已将 direct collector 与 repeated mux grammar 分离并恢复该精确 Oracle。全量 644 case 仍待成功退出，禁止发布。

## 已尝试

- 精确双公共根数组和至少一个公共/私人对照通过公开入口双跑；两个公共根各一设施、各自总线完整，且全质量注册表通过。
- 远距公共根案例有自然红灯、修复后绿灯、成功边界、故障注入和覆盖驱动相邻组合；所有适用质量指标对每个新用例均执行。
- 旧公开图、历史 corpus、全量测试、打包与发布门均通过；任何复发输入加入永久 exact-set。

# 库文件与器件合约

## 文件层

drawclock 接受一个或多个 draw.io 自定义库 XML 文件，也接受目录。目录递归扫描 `.xml`，路径稳定排序后合并；同一路径去重，不同文件出现相同 `title` 时失败，禁止静默覆盖。

每个文件必须只定义一个器件。文件仍使用 draw.io 标准格式：外层 `<mxlibrary>`，文本内容是只含一个对象的 JSON 数组。不增加 drawclock 私有根对象、清单包装或类型映射。文件名不参与识别，器件类型只取条目的 `title`。

单个条目至少包含：

- `title`：全局唯一的器件类型，也是输入 JSON 的 `kind`。
- `w`、`h`：默认选择框尺寸，必须与内部几何一致。
- `xml`：未压缩 XML 或 draw.io 压缩负载。

条目内部使用一个带 `label` 和元数据默认值的 `object` 包裹一个顶点 `mxCell`。不要再在 `mxCell` 内嵌第二个 `object`。`mxCell` 的 style 必须携带端口点、固定尺寸和标签显示规则。

## 数据边界

通用字段只有：

- 库层：`title`、`w`、`h`、`xml`。
- 图节点层：实例名、`kind`、可选 `source`、可选 `layout_column`。
- 其余对象属性是该器件模板自己的显示元数据，例如标签占位符值；它们不能被布局器用来猜类型或连接关系。

不要发明 `component`、`xxx_kind` 一类并行类型字段。类型只有一个事实来源：`kind == title`。

## 目录与合并

原器件库是一个目录，目录中的每个 XML 对应一个器件。目录层级只影响维护，不影响运行语义：

- 每个 title 在合并结果中唯一。
- 引用的图片或模板必须能在离线发行包中解析；优先使用自包含 XML/SVG。
- 文件名不参与器件识别，不可用文件名替代 title。
- 单文件零条目或多条目均拒绝，避免文件边界和器件边界不一致。

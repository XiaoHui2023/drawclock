# 生成与验证规则

## 生成顺序

1. 为每个逻辑器件生成稳定、唯一的实例名。
2. 从目标器件库选择真实 title 写入 `kind`。
3. 建立所有节点后生成 source 引用，避免引用不存在的实例。
4. 查询目标输入连接键和上游输出连接键；不要按 mux、pll 等名字猜端口。
5. 仅在用户确有列偏好时写 `layout_column`；不要把算法算出的 rank 回写为偏好。
6. 使用稳定键顺序输出，便于 diff；语义不能依赖对象书写顺序。

## 前置验证

在布局前一次性检查并汇总报告：

- 顶层为对象，每个值为对象；
- kind 存在且 title 在合并库中唯一；
- source 类型正确、对象非空；
- 每个引用实例存在；
- 输入键能唯一映射到目标端口；
- 输出后缀能唯一映射到上游端口；
- layout_column 是整数且不是布尔；
- 三个频率字段如果存在，必须是字符串或非布尔数字；
- 图无不支持的有向环。

验证失败不得开始布局或写出半成品。

## 数据层分离

公开 JSON 是逻辑层。内部布局结构可以包含 cell id、绝对坐标、尺寸、style、waypoint、logical name 和显示副本，但不得要求用户维护这些字段。源副本只存在于渲染层，验证时映射回同一个零入度逻辑节点。

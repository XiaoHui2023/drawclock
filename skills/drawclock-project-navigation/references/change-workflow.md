# 修改工艺

1. 把需求翻译成可观察不变量和失败反例。
2. 搜索同类实现、测试和文档，确认唯一事实来源。
3. 为原始错误建立最小反例，同时加入重命名、顺序和尺寸扰动，防止按示例打补丁。
4. 在正确层做结构性修改；保持公开 CLI 简单，内部自动选择最佳方案。
5. 运行聚焦测试、属性语料、质量测试和完整测试。
6. 生成真实 SVG，解析坐标、端口、线段、可见范围和 viewBox；必要时人工查看代表图，但人工查看不替代机器门。
7. 比较修改前后的质量向量和耗时，记录退化与取舍。
8. 更新用户文档、项目 skill、设计记录和发行说明中的相应事实。
9. 真实组包，解压后分别运行冻结程序和 `python -I -S src` 源码门。
10. 提交、推送、等待 Release，下载远端资产再次验证。

完成定义是“真实发布资产可消费”，不是“本地单测通过”。

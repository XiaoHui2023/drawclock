# 多对多复现与几何 Oracle

## 证据关系

问题 ID 保持独立，测试文件不要求一对一。`tests/reproduction-corpus/` 是正常 JSON 搜索语料；每个
case 可由 `tools/feedback_layout_reproduction_oracle.py` 直接显示多个问题，一个问题也可出现在多个
case 中。总体覆盖按 `case -> observed issue IDs` 的二部关系计算，没有直接几何检测的边不存在。

正式证据由 `tools/run_feedback_reproduction_corpus.py` 生成。它从
`tests/reproduction-corpus/evidence-corpus.json` 选择稳定 case，在各自冻结 revision 的公开 CLI
运行两次，保存原始 SVG、日志和统计报告，并签发逐问题收据。跨 revision 的额外结果可以保留在
报告中，但不能混入另一 baseline 的问题收据。

## 独立统计

Oracle 不导入 `src`，只读 JSON 与最终 SVG。它先完整绑定逻辑节点、渲染节点、逻辑边、渲染边和
端口；逻辑网络键为“源节点 + 输出端口”，同一器件的多个输出不得合并。再去重复/共线航点，区分：

默认圆弧跨线以 SVG `A` 命令表现时，Oracle 只接受同轴的项目跳线弧，并按弧端点恢复原始正交
线段；非同轴弧或其它曲线命令必须失败关闭。

- 不同网络正交线段的内部交叉事件与去重坐标；
- 端点接触、同网分叉和不同网共线重叠；
- 逐边曼哈顿长度、折点和相交边；
- 同一根网络的 split–rejoin 环；
- 同一逻辑根跨多个显示副本的环秩；副本只改变物理起点，不得把同网重叠环藏成多个单边物理组；
- 低复用零入度根的可行位置反事实；
- 物理显示设施级的可行位置反事实：逻辑根总扇出不能掩盖只服务一条边的显示副本；候选可同时
  平移消费者所在列及其右侧后缀，为完整器件可视框和标签打开净空走廊；
- 同一零入度逻辑根的设施分配反事实：允许在一次候选中拆出一条远端支路、重接精确端口并回收
  空设施，禁止把“先产生非法中间态”当作拒绝最终合法复合候选的理由；
- 独占输入支路与固定目标端口的纵序反转。

`tools/svg_layout_quality_oracle.py` 是 Agent/test 的稳定入口，输出逐节点、逐边、逐源端口网络报告；
它与生产 CLI 分离。`skills/clock-layout-algorithms/scripts/layout_statistics.py` 读取生产内部诊断，只用于
定位候选阶段，不能替代独立最终 SVG Oracle。

“多余折点”或“根位置不佳”只在替代几何不碰节点/标签、不增加交叉或重叠、不增长，且目标指标
严格改善时成立。根按零入度且有输出判定，不按 `source`、`from` 或其它器件名特判。
设施反事实必须以物理锚点实际服务边集判定，不得用逻辑根总出度代替物理出度。验收顺序固定为
端口/方向/碰撞/异网重叠与同网环等硬门，然后是源诱发交叉、交叉点、交叉事件、折点、线长，
最后才是面积。这样扩宽一小段消费者后缀可以换取消除大绕路，但压缩画布不能换取额外折点。

物理锚点与可视框必须按最终 SVG 的物理身份/端点归属保存，不能以逻辑名称为唯一键；别名共享名称
会让后一个框覆盖前一个框。无交叉二折线是高风险信号，但只有“纵移完整单边根设施并重接端口”
的反事实同时通过器件、文字、反向穿越、异网重叠、交叉和长度门，才登记为直接 witness。
根列反事实还必须尊重整齐度：仅缩短一条已经笔直且无交叉的线，不足以把设施从已使用规范列移走；
候选至少要严格减少交叉或折点。

若一个坐标 owner 改变消费者后缀，下一 owner 不得继承未经证明覆盖该变换的增量 assessment。以完整
最终几何重建基线并交替运行，直到两个 owner 都无接受项；否则“前阶段不可行、后阶段新变可行”
的用户反馈会逃逸。该精确收敛必须受拓扑工作预算保护，压力层不得因共享 eligibility 条件误入逐设施
全图搜索。

## 复现顺序

1. 先运行生成器构建简单、边界、组合和压力 JSON；对全部产物形成问题结果矩阵。
2. 缺失问题只扩展相关特征：根类型、复用度、端口数、链深、消费行距、输入顺序、列自由度和规模。
3. 覆盖全部问题后比较失败样本与没有症状的样本，记录触发规律、反例和版本边界。
4. 最后才制作综合 example；它用于展示交互，不替代各冻结版本上的正式失败收据。
5. `reproduced` 只解锁产品修复；只有旧版失败、当前通过、邻近回归和 release 门全通过才可发布。

`tools/run_feedback_fix_verification.py` 对当前公开 CLI 同样双跑，并要求逐问题 Oracle 明确返回“症状
未观察到”。修复收据绑定旧红灯收据、源码树、器件库树、runner、Oracle、输入和原始 SVG；release
门逐哈希重验，手填 `baseline_fails/current_passes` 不能放行。上述对象均为文本，哈希前统一把
CRLF/CR 规范化为 LF，使相同 Git 内容在 Windows 工作区与 Linux CI 中保持同一身份；不得用
操作系统分支或跳过血缘检查掩盖换行差异。
源码树身份只包含产品源码；`__pycache__`、`*.egg-info` 等由解释器或打包器生成的缓存必须排除，
否则一次正常构建就会让收据在干净 checkout 中失效。
树记录先转换成仓库相对 POSIX 路径字符串，再按字节序大小写敏感排序；不能直接排序
`pathlib.Path`，因为 Windows 与 Linux 的路径比较规则不同。

器件种类、节点数量、扇出和不等深链只是触发前提。每个缺陷 Oracle 必须另有最终几何 witness，
并配置“相同前提但无症状”的干净反例；否则属于 Oracle 假通过。

禁止改写 SVG、monkeypatch、故障注入或测试专用入口来签发自然复现。人工几何只可校准 Oracle。

# 规模化与确定性

## 复杂度控制

- 邻接表、入度、rank 和连通分量使用 `O(V+E)` 结构。
- 交叉与碰撞统计使用 sweep line、区间索引或空间桶，避免全量 `O(E²)`。
- 路由通道来自障碍物边界和端口，而不是扫描整个画布网格。
- 对接多路下游的网络构造共享干线，然后路由分支，避免为每条边独立搜索相同纵线。
- 候选生成设置内部早停：连续候选不改进且硬门通过时停止；不要暴露给 CLI。

## 多层与分解

大型图按弱连通分量、源消费簇或重复支路块分解，块内布局后再进行块间排序和全局通道分配。分解必须保留跨块端口边，不能把局部最优当作全局完成。

当前维护范围使用 64 与 128 终端的代表性复杂测试观察工作量变化；它们不能替代小型反例，也不证明 512 及以上压力规模。性能优化必须在质量向量不变或更优时才接受。

局部精确搜索也必须由结构工作量控制。可使用 `gap_pair_work / (|V| + edge_span_load)` 一类由拓扑
投影得到的压力比，选择两种同合同求解层：低工作量层枚举连续坐标并逐候选执行独立几何排序；
高工作量层只选择最右可行规范列，再由相同整图硬门和质量向量验收。禁止按 clock 数、样例名称或
外部“最大规模”切换，也禁止为了速度绕过端口、碰撞、异网重叠或同网环检查。

## 确定性

所有遍历、候选和平局都使用稳定键。相同 JSON 与器件库应产生相同节点坐标、waypoint 和 SVG 顺序。确定性使质量差异可比较，也避免“多跑几次碰到好图”。

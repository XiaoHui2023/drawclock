# 质量目标与门禁

## 硬门

- 每个配置节点至少有一个对应渲染节点；只有零入度源允许显示副本。
- 每个 source 引用恰好生成一条逻辑边，且连接到正确的源/目标端口。
- 端点与可见引脚绝对坐标一致；所有线段正交。
- 节点本体不重叠；边不穿器件、标签或自身器件；异网线段不得有任何超过浮点容差的正长度共线，不能用“短于某个视觉阈值”放行。
- 所有有向边整体从较小 rank 指向较大 rank；SVG 边界覆盖节点、标签、线和跨线符号。
- 同一物理源输出端口的正交线段并集必须为树，不允许先分开、再合并、再分开的环；不同输出端口
  独立统计。

## 优化指标

按顺序比较候选：

1. 交叉总数、不同交叉点数、每条边的交叉点/交叉对事件/不同相交边数、每个逻辑源所有出边的交叉归因；
2. 总折点、单边最大折点、可消除折点；
3. 曼哈顿总长度、异常绕行比、最长竖向贯穿；
4. 同列偏好满足率、简单链直线率、支路列方差；
5. 去除器件和标签后的空白面积、总面积；
6. 运行时间和峰值内存。

每条边还要报告完整曼哈顿长度、横向/纵向长度、最长竖段、折点、线段数、效率比、端点纵向跨度（像素与典型行距单位）、两端之间的实际视觉行数、同源端口扇出数和不同相交边数。每个逻辑节点（包括叶节点）报告入度、出度、直接下级数、源端口网数、显示锚点数以及出边长度、折点、交叉聚合；每个有出边节点另报告最大纵向行距和最大夹行数。独立 Oracle 必须从最终可见几何复算这些值并与生产报告逐项相等。共享同一源端口的重合干线属于同网 junction，不计为交叉。

大图统计不得为了列举所有相交边而物化扇出边的笛卡尔积。用区间/扫描线找到交叉几何后，对参与边累计交叉点集合和交叉对事件计数，空间保持与边数、真实交叉事件近似线性。

测试集不能从已有测试反推“覆盖全面”。先在 `layout-feature-coverage.json` 冻结功能和设计质量要求、
状态与环境，再声明高风险二元/三元交互；每个特性必须同时有成功和故障/边界角色，每个交互必须有
直接 Oracle。用户反馈缺陷另记问题账本并走自然复现授权；新设计要求不伪装成旧缺陷，但注册表缺项
同样阻断发布。机器校验器还要以删除场景、删除交互映射和伪造 pytest 节点的 mutant 证明自身不会
误放行。

面积和耗时不能覆盖前面的视觉质量退化。

用户反馈复现采用多对多 corpus：测试载体可共享，但每条问题必须由自己的直接 Oracle 在最终 SVG
中直接检测。正式收据必须绑定 `corpus_id`、`case_id`、`observed_issue_ids`、冻结 revision、输入、
公开命令、runner/Oracle 和产物哈希；缺失边绑定、曲线路径无法精确解析、入口未到达或产物缺失均
fail closed。详细流程见 `feedback-reproduction-and-geometry-oracle.md`。

## 反例族

- 单链、树分支、双源 mux 汇聚；
- 长短不对称输入：`root→gate→div→mux` 与 `root→gate→mux`；
- 一分二末端紧邻单末端，防止末端交换后交叉；
- 同一源跨近簇与远簇，检查一条干线或源副本选择；
- 三个典型行距以内保持单源，刚超过三行即形成候选；另用约四行的中距离样本证明优化不依赖“超远”空带；
- 同行消费者与上方四行消费者必须允许两个显示锚点；三个以上相互远离的消费带按同一设施成本选择任意多个锚点，不得固定截断为二；
- 多源交错扇出不得使用固定“全图最多 N 个副本”门槛；改为每个别名必须服务至少一条逻辑边、物理锚点数不得超过该源出边数、相邻锚点不可按设施成本无损合并，且完整候选必须实际减少交叉或扣除开设成本后减少走线；
- 复杂多源语料至少组合非周期不定行距、不同根复用度、完整/稀疏多输入器件、部分重叠根集合、汇聚后扇出、汇聚输出再与另一根汇合和不同链深；Oracle 要量化根祖先签名、共同后代根对和消费间隔分布，旧浅层语料必须由突变测试拒绝；
- 同一复杂语料整体重命名、顶层对象逆序和多输入成员逆序后，拓扑量纲与所有硬门仍须成立；这三种变形必须组合执行，不能只分别通过简单图；
- 注入一处异网正交交叉，要求两条边及两个逻辑源均准确归因一次；同网共享干线不得误报；
- 在无节点、标签和其它线路的净空通道内给原本水平直线注入矩形凸起；即使交叉数仍为零，也必须以更短、少四折点的单调路线将其拒绝；
- 长标签、端口上下错位、多输出、缺省 mux 输入；
- 多列相似支路及 `layout_column` 共列；
- 随机重命名、交换输入顺序、扰动器件尺寸和端口，防止按测试名称打补丁；
- 512～4096 终端规模，检查质量不变量与增长趋势。
